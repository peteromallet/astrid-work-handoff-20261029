## Reading key and depth

`unit` means focused pure behavior; `mocked integration` means filesystem/CLI/orchestration with injected dependencies; `real boundary` means an actual generated file, corpus, restricted loader, or external-format boundary; `static source` means source-text or manifest inspection; `snapshot` means committed golden comparison; `property` means generated/invariant-based checking; `live` means an actual external service/runtime boundary (none of the assigned files is a live Comfy boundary). `Deep` means assertions and fixture setup were read; `medium` means test bodies were sampled; `shallow inventory` means classification from names, test definitions, and assertion patterns without claiming full semantic review.

## Deep findings and evidence

1. The strongest existing independent oracle is `tests/parity/test_independent_readback.py:275-438`: synthetic and multi-edge graphs are rebuilt independently, typed boundaries are compared, and the corpus records checked items. `tests/property/test_emitter_fuzz.py:229-414` adds generated shapes, slot bounds, wire-only payload preservation, and deterministic JSON. These protections should be retained as the semantic/topology gate when tests are consolidated.

2. `tests/test_workflow_bundle.py:48-190,540-677` is the key direct owner for identity, restricted loading, revisions, legacy sidecar handling, and strict validation. It currently exercises a `format_version: 1` sidecar in the inspected section (`:550-560,606-677`), while the adopted direction requires a closed v2 `bind`/`custody`/`presentation` envelope and sibling-pair staging. This is an omission, not grounds to delete the legacy tests: add v2 positive, missing/mixed-generation, duplicate-key/unknown-key, duplicate-label, value-edit, structural-edit, and atomic no-write cases.

3. `tests/test_template_roundtrip.py:280-322` checks repeated load/compile and UI link materialization, but its oracle is `semantic_digest`/compiled API and link counters. It does not assert that Python contains no custody/replay machinery, that JSON contains no runtime values or semantic edge authority, or that a changed prompt/seed remains loadable with unchanged custody. Preserve its corpus breadth and add those explicit authority assertions.

4. `tests/test_emitted_no_helpers.py:42-57` is a useful corpus cleanliness tripwire, but it only regex-scans helper names in `raw_call` text. A false negative can arise through aliases/indirection, and a false positive can reject an intentionally non-resolvable helper without checking provenance. Replace only when a replacement asserts both the readable-source contract and successful restricted load/independent readback; until then keep it as a cheap guard. `tests/test_workflow_helpers.py:3-7` is similarly a two-assertion static guard and should not be treated as semantic coverage.

5. `tests/edgecases/test_determinism.py:30-62` has two tests deriving equality from the same emitted text (`:35-48` compares text, then its SHA-256) and a third repeats text equality across instances (`:59-62`). The hash test adds no independent protection if text equality passes. Consolidate the redundant hash assertion into a test that compares the complete staged pair (Python bytes plus canonical JSON) and verifies generation/custody determinism; preserve the cross-instance case.

6. `tests/test_ui_emitter_parity.py:142-176` and `tests/test_template_roundtrip.py:280-301` both provide corpus-wide parity/materialization checks, but their oracles differ: the former uses offline emitter/normalizer self-consistency, while the latter compares emitted/materialized link counters. They are not automatically noise. Consolidation is safe only if the retained test keeps the independent Python-to-UI projection oracle, exact link identity/multiplicity, unsupported-boundary failures, and representative media/template coverage.

7. `tests/test_gold_template_alignment.py:65-220` and `tests/test_v26_canonical_parity.py:11-124` are useful regression nets but rely substantially on overlap/counts or baseline hashes. Counts can pass while edges, values, output slots, or custody ownership are wrong; byte hashes can fail for harmless formatting. Keep focused unique type/output/value assertions, but make the independent graph/API comparison the acceptance oracle before considering consolidation.

## Recommended focused test set for the adopted direction

Tier 1 (must add/strengthen before implementation validation):

- A pair-publication matrix around `workflow_bundle`: one readable `workflow.py` plus `.vibe.json` v2; exact closed schema; deterministic generation/custody digest; duplicate-key/unknown-key/non-finite/malformed nested rejection; complete scope-local labels/order/classes; presentation foreign-key validation; no semantic edges/runtime values/duplicate ready metadata in JSON.
- Authority tests: prompt/model/seed/mask/duration and formatting/comment edits remain loadable; constructor/topology/output edits either rebuild correctly or fail with a structural diagnostic; presentation edits affect only UI materialization; JSON cannot overwrite Python values/topology.
- Atomic fail-closed tests: missing, stale, mixed-generation, wrong identity, wrong custody digest, and malformed companion leave existing destinations unchanged; restricted loader resolves the same pair as registry and copy-to-recipe.
- Replace regex-only cleanliness with AST/source inspection plus restricted-load and independent-readback criteria. Retain the regex as a fast diagnostic if inexpensive.

Tier 2 (preserve and align):

- Keep the independent readback/property fuzz, recursive emitter, virtual-wire, UI materialization/parity, H3, multi-output, finalize metadata, provenance, and copy-authority protections. Parameterize them over scratchpad/legacy and v2 canonical pair paths where behavior is shared.
- Use separate oracles: canonical semantic graph/API, independently reconstructed Python topology/handles, canonical JSON schema/digest, and presentation materialization. Do not let the same serializer produce both expected and actual.

Tier 3 (consolidate/defer):

- Consolidate only redundant text-hash/count/baseline checks after preserving their unique negative cases and corpus breadth (`test_determinism`, selected gold/v26 parity, snapshot overlap, virtual-wire round-trip overlap).
- Defer analysis, upload, release, execution-spine, reporting, asset, and lens suites for this slice; they are not deletion recommendations. No deletion is justified without the replacement criteria above.
